## 1. บริบท — ต่อยอดจากอะไร และทำไมต้องมี

- ผู้ใช้คือใคร (staff / head / admin / คนทั่วไป) และต้องการอะไร (1–3 บรรทัด)
- ต่อยอดจากส่วนไหนของระบบ (เช่น `_template`, `routes/links.js`, ตาราง `research`)
- เกี่ยวกับโมดูลอื่นในกลุ่มหรือกลุ่มอื่นอย่างไร (อ้าง "สัญญาระหว่างกลุ่ม" ใน `docs/features.md`)

## 4. สิทธิ์และความปลอดภัย

| การกระทำ | ใครทำได้ | ถ้าไม่มีสิทธิ์ |
|---|---|---|
| ดูรายการของตน | เจ้าของ | 401 ถ้าไม่ล็อกอิน |
| แก้ / ลบ | เจ้าของเท่านั้น (`user_id` ใน `WHERE`) | 404 |
| <เช่น อนุมัติ> | <เช่น `head` และไม่ใช่เจ้าของคำขอ> | 403 |

- Input ที่ต้องตรวจด้วย zod: <ฟิลด์ + ความยาวสูงสุด + ชนิด> · URL ต้องเป็น http(s)
- ข้อมูลที่ห้ามส่งออกทาง endpoint สาธารณะ: `userId`, อีเมลส่วนตัว, รายการที่ซ่อน, ...

## 8. Acceptance Criteria — นิยามของคำว่า "เสร็จ"

ทุกข้อต้อง **รันได้จริง และระบุผลที่ต้องเห็น** (เปิด `npm run dev:api` ไว้อีก Terminal)

0. ล็อกอินเก็บ cookie ไว้ใช้ข้อต่อไป (รหัสผ่านคือค่า `SEED_USER_PASSWORD` ใน `.env` — ห้ามเขียนรหัสจริงลงใน spec)

   ```bash
   set -a; . ./.env; set +a   # โหลดค่าจาก .env (Git Bash) — ถ้าใช้ PowerShell ให้ใช้ Git Bash แทนสำหรับคำสั่ง curl ในหัวข้อนี้
   curl -s -c cookie.txt -H "Content-Type: application/json" \
     -d "{\"email\":\"kamon.j@university.ac.th\",\"password\":\"$SEED_USER_PASSWORD\"}" \
     http://localhost:4000/api/auth/login
   ```
   ต้องเห็น: JSON ที่มี `"user"`

1. ...

   ```bash
   curl -s -b cookie.txt http://localhost:4000/api/<ชื่อ>
   ```
   ต้องเห็น: `<ผลลัพธ์>`
